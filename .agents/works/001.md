# Streamable Proxy Plan

## Goal
Build a small OpenAI-compatible proxy server for configured provider agents. The request route contract is:

`/{agent}/v1/{...segments}`

The `model` value stays in the request payload, not in the URL path.

## Route contract
- `/nvidia/v1/chat/completions`
- `/nvidia/v1/models`
- `/nvidia/v1/responses`

These are resolved to the configured upstream provider for `nvidia` and then forwarded to the provider’s OpenAI-compatible API.

## Implementation plan
1. Keep a clean config registry for agent and provider defaults.
2. Merge default config with secret config in a single active config object.
3. Parse the incoming URL into `agent` and remaining route path.
4. Validate agent existence and required config before forwarding.
5. Forward the request body and headers to the selected upstream provider.
6. Preserve upstream status, body, and headers for the client response.
7. Log request lifecycle and upstream errors in structured output.
8. Test valid routes, invalid routes, and upstream forwarding behavior.

## Notes
- The model is intentionally not in the path; it remains in the OpenAI-compatible request payload.
- This keeps the proxy aligned with typical OpenAI-style clients while still allowing multi-agent routing.
- The next evolution is adding richer provider validation, streaming compatibility handling, and retry/error policy improvements.
